# Parser fuzzing

The isolated fuzz workspace exercises EWF positioned reads, EWF1/EWF2 logical
catalog parsing and entry reads, and the AFF4 ZIP, metadata, stream, and
verification APIs. Its seeds are synthetic; complete images are generated by
the writers. Fuzz-only dependencies are excluded from the normal workspace and
from the published EWF package.

`ewf_catalog` has raw UTF-16 catalog modes so mutations reach the parser without
being stopped by container checksums. Its other modes open complete L01 and Lx01
images, including split sets, and make bounded strict reads from catalog entries.
The raw seeds include nested entries, extents, a duplicate-data offset, a
data-bearing parent, and an unpaired UTF-16 name. Complete image seeds include
names with slash and backslash. The target limits traversal and read sizes;
it does not verify every entry or replace the external corpus gate.

## Run on Linux or WSL

From the repository root:

```sh
rustup toolchain install nightly-2026-07-16 --profile minimal
cargo install cargo-fuzz --locked --version 0.13.2
bash scripts/fuzz-smoke.sh 30
```

Each target runs for the requested number of seconds after compilation. Increase
the final argument for longer runs. The script limits inputs to 1 MiB, bounds
process memory and time, and applies small AFF4 work budgets. The EWF parser
limits also apply. The script does not use network targets or scan evidence
directories.

## Results and failures

Corpora and artifacts are ignored by Git. Keep a failing input and its invocation
locally, and report it privately as described in the
[security policy](../SECURITY.md). Do not commit private evidence as a seed or
reproducer.

A passing bounded smoke run does not rule out
parser defects. Sustained campaigns, multi-segment and multi-volume interactions,
and additional native producer seeds require separate coverage.
